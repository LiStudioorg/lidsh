# lidsh 架构总纲（Go + Vue 3 复刻 DeepSeek Harness）

> 依据：对已安装的 `@deepseek-ai/dsh@0.1.5-rc.3`（230 个包 / 32 万行编译产物）的实测逆向。
> 本文只写**已在产物中验证过的事实**；未验证处标注「待逆向」，由 `core-semantics.md` / `integrations.md` / `ui-tokens.md` 补齐。

## 0. 一句话结论

DSH 不是「一个 CLI + 一个网页」，而是：

```
一个通用插件框架 (Cordis)
  + 一套声明式配置树组装 (cordis.patch.yml 分层 patch)
  + 一套类型化 RPC 复用层 (typert: zod codec → WS mux)
  + 一个 agent kernel (session 事件溯源 + agent loop + 20 个工具)
  + 一个 React 前端（45 个 ui-* 包，81KB CSS）
```

复刻的**难点不在 agent loop（仅 ~2k 行）**，而在「分层可覆盖的配置树」和「前端 45 个 UI 包之间的插槽契约」。本方案优先保真前者（你要求「完美复刻」），UI 用 Vue 3 重写但**像素级照抄 CSS 变量与布局尺寸**。

## 2. 必须复刻的三层架构

### 2.1 配置树组装（最高优先级，「完美复刻」的核心）

DSH 的启动 = 把若干 **patch 层**按序打到一个空根上，得到一棵 loader 条目树，再交给 Cordis 按服务可用性驱动激活。

**真实层序**（`README.md` + `dsh-app-boot/lib/index.js`）：

```
空根
 → dsh.profile.bundles 顺序的每个 bundle 的 cordis.patch.yml
 → <profile>/cordis.patch.yml         (用户 profile 层)
 → $DSH_HOME/cordis.patch.yml         (home 层)
 → --patch 覆盖层
```

**官方 profile 模板**（`dsh-app-boot/lib/index.js:328-349`，逐字）：

| profile | bundles | patchReload |
|---|---|---|
| `web` | `dsh-base`, `dsh-web-app` | `live` |
| `headless` | `dsh-base`, `dsh-headless` | `startup` |
| `sdk` | `dsh-base`, `dsh-sdk-app` | `startup` |
| `acp` | `dsh-base`, `dsh-acp-app` | `startup` |
| `sdk-minimal` | `dsh-sdk-minimal` | `startup` |
| 自定义 | `[dsh-base]` | `live` |

**patch 算法**（`applyEntryPatches`，`dsh-app-boot` 内联于 `cordis-plugin-include` 区域，完整可照抄）：

1. `structuredClone(data)`，输入永不变更（防止热重载把旧值烤进缓存）。
2. 递归建 `id → entry` 索引，**group 行的子条目在 `entry.config` 数组里**（`entry.group && Array.isArray(entry.config)`）。
3. 逐 patch：
   - `insert` + 有 `id`：目标必须是 group，否则告警跳过；`target.config.push(...insert)`；随后 `buildMap(insert)` 让**同层后续 patch 能引用刚插入的行**。
   - `insert` 无 `id`：`data.push(...insert)`。
   - 非 insert：`id` 必填；未命中 → 告警跳过。
   - `name` 守卫：`name !== target.name` → **告警并整条跳过**（防误改）。
   - 其余字段 **整行覆盖** `target[key] = value`（含 `config` 整体替换，**不做深合并** —— patch 文件头注释明确说明「A patch replaces the targeted row's whole `config` rather than merging into it」，因此随模式而异的值必须留在各 mode bundle 里）。
4. 未命中只 warn 不报错，`--dump-config` 与启动共用同一函数，保证 dump 永不漂移。

条目行形状：`{ id, name, config?, group?, disabled?, ... }`；`!!js` 表达式（如 `dshHomePath('sessions')`）在解析期求值。

**Go 侧映射**（类型安全且保留全部语义）：

```go
type Entry struct {
    ID       string          `yaml:"id"       json:"id"`
    Name     string          `yaml:"name"     json:"name"`
    Group    bool            `yaml:"group,omitempty"`
    Disabled any             `yaml:"disabled,omitempty"` // bool 或带条件的形式
    Config   json.RawMessage `yaml:"config"   json:"config"` // 未命中前不解释，保覆盖语义
    Children []*Entry        // group 时 Config 解析出的子条目
}
// ApplyEntryPatches(data []*Entry, patches []*Patch, warn func(string, ...any)) []*Entry
```

`config` 用 `json.RawMessage`/`yaml.Node` 持有，**是「整行覆盖不深合并」这条语义的关键**：一旦在合并前反序列化成 Go struct 就丢失保真。

模块注册表取代 npm 解析：`map[string]ModuleFactory`，`name` 字段查表；`dsh.bundle.patch` 概念映射为「编译期注册的一张 patch 常量」。行 id 保持与 DSH 一致（`llm` / `session` / `typert-gateway` / `agent` / `settings` / `credentials` / `webserver` / `ui-theme` …），便于直接对照 DSH 的 patch 文件做兼容测试。

### 2.2 类型化 RPC（typert → Go）

DSH 用代码生成：`FaceModel` → zod codec + `typert.host.js` + `typert.remote-client.js`（文件头 `Generated by @deepseek-ai/dsh-typert-generator from FaceModel — do not edit.`）。

Go 侧复刻策略：**用 Go struct + tag 单向生成 TS 类型**，比反向工程 zod 更省事，且能生成 codec 校验所需的 JSON Schema：

- Go：`struct` + `json` tag → 运行时用 `reflect` 校验（对齐 zod 的边界校验角色）。
- 生成：`go run ./cmd/gen → web/src/protocol/*.ts`（类型 + 方法名常量表）。
- 保持 DSH 的返回约定：`RemoteResult[T] = {ok:true,value} | {ok:false,error:{code,details}}`，**错误不抛异常**；错误码表初始对齐 `gateway/bad-request`（带 `issues`）、`gateway/cancelled`、`gateway/internal`。
- 命名空间：DSH 有直接 `namespace/method` 与带作用域 `contextKey:namespace/method` 两种，作用域靠调用时的 `agent` 上下文投影（`types.d.ts` 的 `TypertRemoteScopeMap`）。Go 侧以 `scope{sessionId,agentId}` 字段显式化。

### 2.3 Agent kernel

- **Session = 事件溯源 + JSONL 追加**（`dsh-session-persistence-jsonl`，`root: !!js dshHomePath('sessions')`）。
- 图片等二进制**不入 append-only 日志**，消息里存 content-addressed 引用，由 `dsh-attachment-local` 解析（patch 注释原文）。
- 投影缓存：`session-projection-cache` 写穿式，`writeEveryEvents: 200` / `writeIntervalMs: 5000`，按 session 一份带版本戳 checkpoint。
- 会话检索：SQLite，默认 `path: ':memory:'` + `openAt: never`（搜索关闭，精确读/标题/血缘仍可用），启用需后层覆盖 `openAt: first-search|startup`。
- 标题：`session-title` + `session-title-first-prompt-llm`（`targetWords:5`、`targetCjkCharacters:10`、`maxInputBytes:4096`、`maxOutputTokens:64`、`timeoutMs:60000`）。
- 默认模型行：`agent-default-model` → `provider: deepseek-official, model: deepseek-flash`。
- 凭据：`$DSH_HOME/.credentials.yaml` + 进程环境继承 + 项目/用户 `.env` 兜底，**per-request 解析引用，不写进进程环境**；Models 页只写该受管文档。
- 设置：`$DSH_HOME/settings.yaml` 热重载，`llm-deepseek:` / `llm-pi-ai:` 段覆盖 adapter 条目；pi-ai 段为空时该 provider 零路由（picker 里不出现模型）。
- 引导期 env 保护：`.env` 不允许设置 `BOOTSTRAP_NAMES` 白名单外的名字（`PATH`/`HOME`/`SHELL`/`NODE_OPTIONS`/`LD_PRELOAD`/`BASH_ENV`/`ENV`… 见 `dsh-app-boot/lib/index.js:948+`），Go 侧照抄这份黑名单。

## 3. 技术选型

### 后端（Go）
| 用途 | 选型 | 理由 |
|---|---|---|
| HTTP + WS | `net/http` + `gorilla/websocket` | DSH 自己用 `ws`；标准库无 WS |
| YAML | `gopkg.in/yaml.v3`（`yaml.Node` 保真） | 复刻 patch 需保留节点，不能过早解码 |
| JSON Schema/校验 | 自研 reflect walker | 对齐 zod 的边界校验角色，避免引入 TS 语义 |
| 事件总线 | 进程内 channel + 类型化 topic | 替代 Cordis 事件 |
| 服务容器 | 自研 `Registry`（依赖声明 + 拓扑激活 + disable） | 替代 Cordis `Service`/`inject` |
| LLM | `net/http` 手写 SSE | 不引 SDK，便于对齐流式事件语义 |
| 嵌入前端 | `go:embed` | **满足你「Vue 3 编译成静态网页塞进二进制」** |

### 前端（Vue 3）
- Vite + Vue 3 `<script setup>` + TypeScript；**不引 UI 组件库**（DSH 也没有，81KB 自有 CSS，引库会导致观感偏离）。
- 状态：Pinia（会话流、连接、设置）。
- Markdown：`markdown-it` + `shiki`（DSH 用 shiki，含 90+ 语言分包，Vue 侧照做按需加载）；主题双份随 `ui-theme` 切换。
- 代码组织照抄 DSH 的插槽化思路：`slots/` 目录 + 组件注册表，让「新面板 = 注册一个组件」，对应 `dsh-client-ui-*` 的 45 包结构（在 Vue 里退化为目录约定 + 一个 registry，不用真的做 45 个包）。

### 构建产物
```
web/  ──vite build──► web/dist ──(构建期拷贝)──► internal/webui/dist
                                              go:embed  ↓
cmd/lidsh ──go build──► 单个静态二进制 lidsh（含全部前端资源 + patch 常量）
```
`make release` = `pnpm -C web build && go build -trimpath -ldflags '-s -w'`。前端在 Go 里只读嵌入，开发期 `pnpm dev` + Go 侧反代。

## 4. 关于你提到的「Vue 3 编译成静态网页变成二进制」

判断正确且可行，两个要点：

1. Vue 3 是**编译器优先**框架（SFC → render 函数），Vite `build` 出纯静态产物，天然适合 `go:embed`。
2. **需要留意的是相对路径与 SPA 回退**：DSH 产物用的是 `./assets/...` 相对引用（`dist/index.html` 实测），Go 侧 embed 时用 `http.FS` + `io/fs.Sub` 要处理好 base path；history 路由需 `index.html` 回退，否则刷新 404。

> 注：比 Vue 更极端的选项是 `vue-ssr`/预渲染，但 DSH 是登录态 SPA，纯 SPA + embed 就够，不必预渲染。
